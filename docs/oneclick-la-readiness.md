# 004 · 新设备 LA 严格出口就绪门槛

状态：**代码候选已实现；未部署 Q4，未开放新设备严格 LA。**

## 原因与现网证据

2026-11-23 对一台连接专用 Wi-Fi 的新 Mac 做只读检测：

- DHCP 默认网关和 DNS 均为中兴 `192.168.5.1`，而 Q4 是 `192.168.5.7`。
- 从 Mac 直接向中兴 `192.168.5.1:53` 查询 `example.com` 得到有效 IPv4 响应；`192.168.5.7:53` 并未监听常规 DNS。
- Mac 当前未报告可用的公网 IPv6，但这**不等于**其它设备、故障期间或所有应用均没有 IPv6/旁路。
- Magic8 原试点验证了 SG / LA 的共享代理基础设施与部分故障恢复。Magic8 采用旧授权控制器，测试不等于新接入设备的同网段 DNS 已受 Q4 控制。

在同一 /24 子网内，设备与中兴之间的 DNS 数据包可以在二层直达主路由器，**无需通过默认网关 Q4**。Q4 的 nftables 无法单独截获这种未经过 Q4 的报文。故仅放开网页或将现有 LA 端口应用到新设备，会错误地承诺“严格固定出口”。

## 本次候选实现

- 004 的 `getOneClickSnapshot()` 新增 `strict` 状态，只接受受限 Q4 Unix Socket 返回的布尔能力证明；旧版控制器没有字段时默认关闭。
- 设备列表仅当 Q4 确认严格 LA 可用**且**中兴确切报告该设备处于配置中的专用 SSID 接口时才开放 LA。频段、名称、IP、Mac 推断都不算。
- 后端切换接口在任何中兴写操作之前重复判断；Q4 新控制器的候选代码也会在 activate/change 阶段重复阻挡无证明的 strict 请求。
- 提供 Q4 私有候选：`outputs/la-readiness/host/rph-oneclick-controller.py`。**此目录按项目策略不进 Git，不代表已部署。** 候选仅在收到 root-only、限定 30 天有效且绑定 SSID7/网关/路由器的已验收网络证明后报告支持 strict。程序绝不自行生成这份证明。不得用软件开关代替真实网络隔离。
- 原有 Magic8 / LAN2 控制器和 SG / 家庭直连保持原样。

## 一次性网络改造要求（不是每台设备重新开发）

优先确认中兴是否支持对专用 SSID 施加**独立子网/VLAN、独立 DHCP 默认网关和 DNS、IPv6 防绕行与跨网段过滤规则**。若当前原厂固件不支持，应使用支持独立 SSID/VLAN 的 AP/路由设备。保留主家庭 Wi-Fi、主 DHCP、FTTR、MLO、Magic8、Windows 既有控制器，不在共享 /24 上同时启用第二套 DHCP，也不要更改全屋 DNS 为 Q4。

如无法建立强制经过 Q4 的网络路径，新设备严格 LA **不能开放**；现有共享 Mihomo 支持 LA 不等于该安全条件已满足。

## 网络完成后必须实测（只针对隔离后的专用网络）

1. 从刚连入的测试设备读取 DHCP 网关与 DNS，确认其使用隔离段和受控 Q4 出口。
2. 单独向中兴 IPv4 地址发出 UDP/TCP 53 查询，确认无法直接取回家庭宽带 DNS 答复；对公网常见解析端口以及应用级 DoH/DoT 验证其实际出口不能绕行。
3. 测试公网 IPv4 只能是指定 LA；公网 IPv6 必须被受控或阻断，且没有备用链路。
4. 用隔离测试设备在保持同一 SSID 的情况下临时断开 LA 通道，验证真实 HTTPS 与 DNS 失败、路由器不会回退到家庭宽带；恢复后仍为 LA。须有独立自动恢复及防断管措施。
5. 复核 Q4 重启与服务异常时防火墙先于代理生效，严格模式默认拒绝；不会影响既有 Magic8、LAN2、其他家庭设备。
6. 只有所有测试通过，才由管理员将 root-only 的短期网络验收证明安装到 Q4，发布新 host/Web，复测一台新设备并记录实际出口。

**当前不满足第 2 项**：Mac 可直接查询中兴 DNS。因此本次不会写入 Q4 的 strict 证明，也不会解除生产 LA 禁用。

## 开发验证

`npm run test:devices`、`npm run test:home-network`、`npm run test:devices:http`、`npm run lint`、`npm run build`，以及 Q4 候选 host 的 `--selfcheck` 与模拟证明校验；不触碰生产网关或 DNS。
