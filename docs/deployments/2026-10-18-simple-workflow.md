# 使用方案与更换流程简化

用户确认后，将日常选择收敛为四种方案：机场＋Webshare、VPS＋Webshare、只用 VPS、只用机场。
Clash 仅显示使用方案和机场节点；多台 VPS 时另显示 VPS 节点。内部连接组隐藏。

网站提供更换 Webshare、机场和 VPS 三个入口；订阅 URL 及授权令牌不变。
Webshare 在浏览器内识别官网命令 / 代理 URL / 四段参数，保存前不提交。
Direct / Backbone 选定后随发布生效。新机场订阅读取失败时保留原配置。
移除或改名原节点后明确提醒重新检查选择。

发布、客户端应用与本机实测是三个不同状态；没有本机控制通道，因此网站不声称后两项已完成。
普通代理与 AI 专用端口共同使用所选方案，没有自动切换出口或直连备用。

## 验收

- `pnpm lint` 与 `pnpm build` 通过。
- 浏览器识别官网形式 curl 参数、核对字段、放弃修改，以及选择接入方式进入待发布状态通过。
- 授权保存发布及移除节点计数通过；真实 NAS 管理会话保存发布通过。
- 四种方案在独立官方 Mihomo 内核中均完成出口检测和 Anthropic HTTPS 请求；前者 200，后者未认证 401。
- 两个 Webshare 方案均保持原出口；VPS 和机场单独使用分别得到对应出口。
- 重新加载独立内核后方案与节点选择保留。故意使 VPS 不可达时，两条 VPS 路径均失败而不换出口。
- 独立内核的机场域名解析曾受现有生产 TUN 假 IP 干扰；隔离测试使用本机生产 DNS 查询得到的真实解析记录。该测试用 hosts 覆盖未进入生产订阅。
- NAS 生成的实际订阅通过官方 Mihomo 解析；两个只读规则端点 200，未认证写入 401。
- 官方 Clash 刷新后实际只显示两个主要分组，保留原机场节点及 Webshare 出口；AI 接口和 Magpie 网关均为未认证 401，未复现 502。

401 仅证明请求路径可达；未验证登录后的账号生成，也不能据一次短时验收保证长期稳定。
所有真实节点、凭据、运行快照及原始测量保留在忽略的 DATA_DIR 中，未进入 Git。
