# 设备管理与部署边界

## 用户操作

设备上网页以设备为主，选择线路即发起相应操作。新设备先走主路由宽带；首次进入网关路径可能需要一次 DHCP 更新，用户只需重连 Wi-Fi。后续 SG / 直连切换在网页完成。

主列表优先显示已管理与可接入设备。非专用无线网络、有线基础设备、离线设备或宿主服务不可用时给出原因。旧客户端功能放入折叠区域，NAS 草稿生成工具不再出现在日常页面。

## 状态含义

| 状态 | 能证明什么 |
| --- | --- |
| 默认直连 | 未登记由网关接管，沿用默认主路由路径 |
| 规则已应用 | 受限宿主控制器确认相应方案及版本 |
| 已观察到流量 | 宿主观察到了该设备匹配的报文 |
| 等待设备流量 | 尚未获得相应流量证据 |
| 接入未完成 | 接入事务未完成，保留直连防护 |
| 人工实测 | 用户曾确认该版本方案的实际出口，属于历史记录 |

运行状态不等同于公网 IP 自动检测。更新方案会清除原版本验收记录。

## 私有网络配置

宿主部署程序写入 `DATA_DIR/.rph-oneclick-network.json`。文件必须是普通文件，建议 root 所有且权限 `0600`；Web 拒绝符号链接、未知字段、超过 16 KiB 或非法网络配置。

仅用于格式说明的合成示例：

```json
{
  "version": 1,
  "lanCidr": "192.168.50.0/24",
  "gatewayIp": "192.168.50.7",
  "routerIp": "192.168.50.1",
  "reservedIps": ["192.168.50.1", "192.168.50.2", "192.168.50.7", "192.168.50.29", "192.168.50.254"],
  "wifiInterfaceAlias": "SSID7"
}
```

示例不是设备默认值。部署时必须与实际宿主授权边界一致；Web 不会根据发现到的设备扩大范围。当前解析器只接受规范的私有 IPv4 `/24`，有效主机地址为 `.1` 至 `.254`，网关与主路由必须位于保留地址集合。

## 权限分工

- Web：认证、路由器设备发现、单设备绑定事务、策略存储与受限 socket 请求。
- 原共享控制器：维护既有已授权设备，按其现有协议应用相应方案。
- 自动接入控制器：维护少量动态接入设备，仅支持已验收的 SG 与直连。
- 共享转发内核和 DNS：承载流量。Web 不直接修改其系统服务、防火墙或宿主默认路由。

服务端先判定控制器可用性，再计算页面可操作能力；私有配置存在本身不代表宿主已就绪。新设备严格 LA 请求在任何网络写入前拒绝。

## 回退与数据

每个接入事务固定同一份已验证网络配置，并记录本次是否尝试新建路由器绑定。此前已存在的精确绑定可被安全复用，当前事务不会把它当作新建记录删除。配置写入结果不明时，只回读并撤销当前事务拥有的精确绑定。

失败后保留单设备直连防护，因为设备可能仍持有指向网关的 DHCP 租约。这样不会要求用户补配 DNS 或 IP。宿主不可达时报告未知/失败，不把旧记录渲染成已成功切换。

## 发布检查

Web 更新应在独立容器使用合成数据验证，再替换单一 Web 镜像。检查两个规则端点、管理认证、私有入口限制、旧与新设备控制器状态；应保持宿主服务进程、动态受管状态和真实规则内容不变。配置迁移、源码包和回滚材料只留在私人部署目录。

该仓库提供 Web 层及其协议测试。实际宿主控制器、网络接口、保留设备和部署凭据由对应安装管理，不能从示例配置推断任意路由器固件都受支持。
