# Route Policy Hub · 网络管理

运行在家庭 NAS 上的私人网络管理页面：查看联网设备、按设备选择上网线路，维护网站规则和已有 Clash / Mihomo 客户端订阅。

## 日常使用

1. 新设备连接专用 Wi-Fi，默认使用家庭宽带直连。
2. 在家庭局域网打开 `/home-network`，用现有管理密码解锁。
3. 为设备选择「新加坡分流 · SG」或「家庭宽带直连」。首次接入如仍走原线路，重连一次 Wi-Fi；以后在网页切换。

设备列表默认显示已接入和可接入设备。线路名称、运行状态与出口实测记录分别显示；MAC、诊断信息和可选客户端订阅放在设备详情中。页面不把“保存了方案”当作实际流量已经通过。

洛杉矶固定出口仅对已完成支持的设备开放。新设备的严格出口仍需完成 DNS / IPv6 防绕行验收，因此界面与服务端都拒绝这类新接入操作。

## 页面

| 路径 | 用途 |
| --- | --- |
| `/` | 常用操作入口 |
| `/home-network` | 设备发现、自动接入、线路切换与状态 |
| `/connections` | VPS、机场、固定出口与客户端订阅 |
| `/policies` | 网站直连或代理例外 |
| `/claude` | 已有 Claude 专用客户端配置 |
| `/network-guide.html` | 使用帮助 |

管理入口保持私有。设置 `LAN_MANAGEMENT_HOST` 后，设备管理、相关 API 和私有设备订阅只接受指定入口，并拒绝来自 Cloudflare 代理标识的请求；管理写操作还需密码认证。只读 `/rules/direct.yaml` 和 `/rules/proxy.yaml` 保持原有路径。

## 架构与边界

Web 容器负责策略、鉴权、设备列表和受限控制请求。实际转发由单独安装的宿主网关、DNS 和设备控制器完成；Web 不获得 `NET_ADMIN` 或 Docker socket。

新设备接入按以下顺序执行：准备单设备直连防护 → 写入该设备的路由器绑定 → 请求网关切换方案。绑定与回退使用同一份私有网络配置，只处理本次操作拥有的记录。已有绑定、其他设备和全局 DHCP 不自动覆盖。

路由器会话写操作带当前会话 token；管理请求串行化，防止互相挤掉登录。控制器不可用或私有配置不合法时拒绝接入，不把配置存在当作控制器已运行。

详见 [设备管理与部署边界](docs/home-network.md)。

## 配置与数据

复制 `.env.example` 到本机 `.env`，由设备所有者填写管理密码、私有管理入口及路由器连接配置。真实文件不提交 Git。

所有可变数据保存在 `DATA_DIR`，包括策略、节点凭据、设备选择、验收记录与私有网络配置。备份应保护整个目录。

自动接入还要求：

- 宿主网关与受限 Unix socket 控制器已单独安装并验收。
- 私有的 `DATA_DIR/.rph-oneclick-network.json` 与宿主允许范围一致。
- `RPH_ONECLICK_ENABLED=1`；模板默认关闭，避免未部署宿主能力就开放接入。

私有配置不会由 Web 猜测或自动补全。现有安装升级时由受限部署程序迁移现状，不需要用户逐设备填写网络参数。

## 本地开发与验证

需要 Node.js 22.13 或更高版本。仓库使用 pnpm 锁文件：

```bash
pnpm install --ignore-scripts
pnpm dev
pnpm lint
pnpm build
pnpm test:devices
pnpm test:devices:http
```

HTTP 测试在本机随机端口使用临时合成数据，验证认证、不可用时拒绝操作及两个规则端点，不连接真实路由器。纯逻辑测试覆盖绑定所有权、失败回退、私有配置、控制器协议与客户端规则生成。测试通过不等同于任意设备已经完成实际出口验收。

旧配置导出工具保留为维护用途：

```bash
pnpm export:home-network --output-dir /absolute/private/new-directory
```

它只生成文件，不部署、不修改网络；下载内容可能含节点凭据，应留在私人目录。

## 容器运行

`compose.yaml` 用于本地构建，`compose.prebuilt.yaml` 用于预构建镜像。设备所有者先在私有 `.env` 中完成配置，再启动：

```bash
docker compose up -d --build
```

示例访问地址为 `http://nas.local:8787`。管理服务应只在 LAN 或经过授权的私人网络内使用。

预构建模板使用只读根文件系统、删除全部 capabilities，只有 `./data` 可持久写入。Web 更新不应改变宿主网关服务、路由器全局设置或已接入设备的运行方案。

## 提交与隐私

不提交真实 `.env`、`DATA_DIR`、订阅地址、节点材料、账号密码、token、cookie、私钥、真实设备身份、私人网段、部署日志或回滚备份。Git 和 Docker 构建上下文均排除这些本地材料。

公开测试只使用合成身份与示例地址。旧运维笔记与试验记录留在忽略的私人目录，公开文档描述当前产品和接口；历史文档明确标注历史，不能作为重新开放管理入口的授权。
